# Approved customer self-service target

Use this contract when changing onboarding, checkout, domain migration or
activation. It records the approved target; current source remains the authority
for implemented behavior, and each change needs its own reviewed scope/evidence.

Customers use magic links. Calendar OAuth is a separate delegated connection,
never social-login activation. Builder work precedes purchase; authenticated CMS
access, payment state, domain authority and first-live delivery are separate
authoritative states. Supported customer journeys cover Dutch and English.

Domain setup and migration are customer self-service. Manual domain work means
guided customer action, not routine operator provisioning. Unsupported provider
capabilities and unknown DNS/TLS/ownership states remain explicit gates. Preserve
Ami Care, active snapshots/routing and every existing commercial obligation;
absence of orders requires evidence before a clean-slate migration assumption.

New numbered variants, post-purchase AI editing, agency accounts and new paid
infrastructure require separate scope. Validated site data and shared rendering
remain the architecture; generated executable code and tenant-specific source
trees are outside this target. Authentication, payment, origin and migration
changes require their own real-boundary tests and independent review.
