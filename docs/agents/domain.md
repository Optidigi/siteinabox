# Domain documentation

Use a single project vocabulary. Read the relevant contracts under
`docs/contracts/` and the engineering/release guidance linked by `AGENTS.md`.
A root `GLOSSARY.md` or `docs/adr/` may be introduced when an actual terminology
conflict or durable architectural decision requires it; neither currently exists.
Keep operational status in tracking issues and machine evidence in its owning
policy/artifacts, rather than creating an additional domain status document.
